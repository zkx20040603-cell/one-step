# 山高万仞只登一步

학습과 생활 계획을 정리하는 대학생이 할 일을 날짜별로 등록하고 완료 표시를 하면 오늘과 이번 주의 진행 상황을 확인하는 서비스입니다.

## 1. 목적
여러 곳에 흩어진 개인 할 일을 한곳에 모아 오늘 할 일과 이번 주 계획을 확인합니다. 작은 실천을 완료 표시하며 진행 상황을 파악하는 것이 목적입니다.

## 2. 사용자
수업, 자기 공부, 생활 계획을 함께 관리하는 대학생 한 유형을 대상으로 합니다. 하루를 시작하거나 주간 계획을 확인할 때 휴대전화 또는 컴퓨터로 사용합니다.

## 3. 공개 주소
- 서비스: https://zkx20040603-cell.github.io/one-step/
- 저장소: https://github.com/zkx20040603-cell/one-step

주소를 입력한 뒤 휴대전화 또는 시크릿 창에서 로그인 없이 열리는지 확인합니다.

## 4. 사용법 (핵심 흐름)
1. `할 일 추가`를 누르고 이름(공백 제거 후 1~120자), 예정일, 카테고리를 입력합니다.
2. `저장하기`를 누르고 해당 날짜에 맞게 `오늘`, `이번 주`, `전체`를 선택합니다.
3. 체크박스로 완료 표시하고 완료율을 확인합니다. 수정, 삭제, 완료 취소도 가능합니다.
4. 새로고침 후 기록이 유지되는지 확인합니다.

이번 주는 기기 날짜 기준 월요일~일요일입니다. 선택 기간 밖의 이전 미완료 일정은 별도로 표시하며 해당 기간 진행률에 포함하지 않습니다.

### 실행 및 수정
`index.html`, `style.css`, `script.js`를 같은 폴더에 두고 정적 서버 또는 GitHub Pages에서 실행합니다. HTML은 구조와 문구, CSS는 반응형 디자인, JavaScript는 일정과 저장을 담당합니다. 별도 설치나 빌드는 없습니다.

### 네 가지 상태 재현
아래 조건을 공개 주소 끝에 붙여 재현할 수 있습니다. 시험 모드는 예시 일정 생성이나 기록 삭제를 하지 않습니다.
- 정상: 기본 주소에서 자신의 시험 일정을 등록합니다.
- 빈 결과: 일정이 없는 날짜/기간을 선택합니다. 할 일이 없다는 안내와 추가 제안을 표시합니다.
- 로딩: `?sim=slow` — 3초 동안 불러오는 중 안내와 `aria-busy=true`, 이후 실제 기록을 표시합니다.
- 읽기 오류: `?sim=error` — 실패 이유와 다음 행동을 안내합니다. `다시 시도`를 누르면 같은 페이지에서 모의 실패를 해제하고 실제 기록을 읽습니다.
- 저장 오류: `?sim=save-error` — 추가/수정/완료/삭제 저장이 실패하며 기존 기록을 유지합니다. 대화상자를 닫고 `다시 시도`를 누른 후 다시 저장합니다.

실제 저장소 문제는 시험 모드를 해제해도 해결되지 않을 수 있습니다. 잘못된 입력은 값 유지, 입력칸 바로 아래 설명, `aria-describedby`, `aria-invalid` 및 첫 오류 칸 초점으로 안내합니다.

## 5. 데이터 출처와 갱신일
| 데이터 | 출처 | 이용 조건 | 갱신 방식 · 마지막 갱신일 |
|---|---|---|---|
| 개인 할 일 | 사용자 직접 입력 | 본인이 사용할 수 있는 내용만 입력, 개인정보 최소화 | 추가/수정/완료/삭제 저장 시 갱신 |
| 날짜와 주간 범위 | 사용자 기기의 날짜 | 기기 시간대 및 날짜 설정 사용 | 화면 열기/기간 변경/창 복귀 시 재계산 |
| 시험 조건 | 직접 작성한 오류/지연 시뮬레이션 | 검증 목적, 외부 API 사용 없음 | 구현 문서 2026-10-14 |

데이터는 현재 브라우저의 localStorage에 저장됩니다. 서버 전송과 인증키가 없습니다. Google Fonts는 글꼴만 요청하며 네트워크가 없으면 시스템 글꼴을 사용합니다. API 키를 나중에 추가한다면 클라이언트 코드에 넣지 않고 GitHub Secrets 등 서버 측 구성으로 관리해야 합니다.

## 6. 검증 기록
정상, 경계, 빈 결과, 잘못된 입력, 실패, 모바일을 구분한 상세 표는 [검증 기록](verification.md)에 있습니다. 공개 사이트에서 추가·수정·완료·새로고침·주간 보기·빈 입력·읽기 실패 복구를 확인했습니다. 아직 확인하지 못한 항목은 `미확인`으로 표시했습니다.

### 고친 것
- 즉시 사라지는 로딩 안내 → 재현 가능한 3초 지연 시험 모드 추가.
- 오류 메시지만 표시 → 실패 이유, 다음 행동, 다시 시도 버튼 추가.
- 일반 입력 오류 → 필드별 오류 설명, 초점 이동, ARIA 연결 추가.
- 읽기 오류 뒤 기간 버튼을 누르면 빈 목록으로 바뀌는 문제 → 복구 전 기간 변경 차단.
- README 구조 → 제공 템플릿의 여덟 항목으로 재작성.

## 7. 알려진 한계
- 실제 브라우저 조작, 모바일 및 키보드 실측은 검증기록을 참고하세요.
- 로그인, 반복 일정, 알림, 다른 기기 동기화, 백업/내보내기는 없습니다.
- 브라우저 데이터 삭제 시 기록이 사라집니다. 브라우저/주소별 저장은 서로 독립적입니다.
- 같은 주소의 여러 탭에서 동시에 수정하면 나중 저장이 우선할 수 있습니다.
- 손상된 저장 데이터는 덮어쓰지 않고 편집을 중지합니다. 자동 복구 기능은 없습니다.
- 휴대전화에서 개발 서버 주소 `127.0.0.1`은 컴퓨터의 웹사이트 주소가 아닙니다. 공개 배포 후 시험합니다.

## 8. 사용한 자료와 AI 도움
- 사용한 자료: 제공된 7주차 「MVP 완성과 검증」 PDF, 실습안내, README 및 검증기록 템플릿을 요구사항 확인에 참고했습니다. 검색 예제 코드를 그대로 사용할 필요는 없어 일정 관리 기능으로 구현했습니다.
- 글꼴: Google Fonts Noto Sans KR / Noto Serif SC(SIL Open Font License), 미로딩 시 시스템 글꼴.
- AI 도움: Codex가 `index.html`, `style.css`, `script.js`, README 및 검증기록 초안, 논리 검사 코드를 작성/수정했습니다.
- 본인 설명: 기획에서 선택한 이유, 직접 확인한 내용, 직접 수정한 부분을 제출 전에 본인의 말로 추가해야 합니다. 현재 AI가 초안 작성했으며 본인 수행으로 표시하지 않았습니다.
- 동료 피드백: 미수집. 실제 받은 의견과 수정 결과만 추가합니다.
